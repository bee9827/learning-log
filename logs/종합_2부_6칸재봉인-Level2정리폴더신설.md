# 종합-인출 2부 — 남은 6칸 재봉인 + `Level2_정리/` 폴더 신설 (정리물은 요약이 아니라 인출의 전사)

> **정리 로그** (학습 로그 번호 시퀀스 밖). 기존 카테고리를 종합·정리하는 세션이라 `logs/NN` 번호 대신 `종합_N부_`로 표기한다.

**날짜**: 2026-07-09 (메타/종합 세션 — 프로젝트 미러 제외)
**범위**: 종합-인출 2부 전체. 같은 날 두 세션(먼저 테스트 칸, 이어서 나머지 5칸)을 하나로 합친 기록. 남은 6칸(테스트 / 인증·세션 / 복잡한 모델링 / 아키텍처·의존성 / Spring 웹 흐름 / 학습법)을 지도 안 보고 인출 → 대조로 빠진 조각·이름 복구 → **학습자 문장으로 재봉인**. 회고 목적이 명확해지며 **정리물을 `Level2_정리/` 폴더의 카테고리별 파일 9개 + 스킬 스냅샷**으로 전환.

분류: 학습법 + 종합

> **내용은 안 적는다.** 각 칸의 목적·저울·흐름은 `Level2_정리/*.md`가 정본. 이 로그는 이 세션이 *어떻게 굴러갔나*(방법·교정·결정)와 **칸별 핵심 한 줄**만 남긴다 — 내용을 다시 요약하면 정리물과 중복이라, 학습자 발의로 얇은 메타 로그로 결정.

## 1. 이 세션이 만든 것

- **1부(종합_1부)와 함께 9칸 전부 학습자 인출로 재봉인 완료.** 2부는 이 로그의 6칸.
- `Level2_정리/` 폴더 신설 — 카테고리 9칸을 표 한 줄(CATEGORIES.md)이 아니라 **풀어쓴 파일**로: 인증세션·복잡한모델링·테스트·DB트랜잭션·외부결제연동·외부API장애대응·아키텍처의존성·Spring웹흐름·학습법.
- **나선형학습-스킬스냅샷.md** — Level 2 종료 시점 스킬 전문을 손 안 대는 기준점으로 박음(방법론 진화 비교용).
- CATEGORIES.md 9칸 전부 갱신(Spring웹 *미탐구* 탈출, 학습법 저울 신설).

## 2. 칸별 핵심 재봉인 (한 줄씩 — 상세는 `Level2_정리/`)

- **🧪 테스트**: 목적이 "변경의 신뢰"→**"책임을 명시하기에 변경이 가능하다"**로 원인까지 깊어짐 + 저울에 둘째 축(**검증하려는 책임이 테스트 단위를 나눈다**: Domain=단위/Service=통합/Controller=슬라이스 or 인수). `@WebMvcTest` 이름 복구. 실패모드=호출·커버리지만 보면 구현만 고정.
- **🔑 인증·세션**: 증표를 매 요청에 실어 보낸다(세션=JSESSIONID/토큰=JWT), 저울=상태 저장하면 무효화 쉽고 안 하면 확장 쉽다. **Signature** 이름 복구.
- **🧩 복잡한 모델링**: 도메인 vs Service = "자기가 든 데이터로 판단되나 + 크기가 작나" 두 기준. 규칙이 Service로 밀리는 지점 = **DB 칸의 출발점**(조회→INSERT race).
- **🏗️ 아키텍처·의존성**: **결합의 성격이 끊는 도구를 정한다**(동기=중립 담당자 Order, 비동기=아웃박스). Order는 유실 방지가 목적, 사이클 끊기는 덤.
- **🌱 Spring 웹 흐름**: 위치가 능력을 정한다(Filter는 forward 커버, Interceptor는 못 감). forward↔once 매듭을 **인증 vs 인가**로 닫음.
- **🌀 학습법**: 재미→주도권→정답 안 주기, 핵심은 **재방문**(i+1·더 깊게·차단이 다 재방문을 위한 장치), 깊이↔폭.

## 3. 방법 — 이번에도 "인출 거칠게 → 대조로 메움"

- **이름 휘발 재확인**(종합_1부 DLQ와 동형): 인증에서 **Signature**가 "페이로드"로 밀려 증발 → 개념은 살아 있고 이름만 복구. 흐름 기반 학습자의 그림자면이 또 나옴.
- **저울류 인출은 거칠게 나온다**(종합_1부 집합/카운트 방향에 이은 반복 관찰): 테스트에서 Service·Controller를 한 덩어리로 인출 → 대조로 분리(Service=DB 경계 통합가치 / Controller=API 계약). 저울류 슬롯은 대조 단계를 더 촘촘히.
- **교정 4건**(전부 학습자가 바로 수용·재정정): ① "암호화"→서명은 기밀성 아닌 **무결성**(Base64는 누구나 읽음) ② "탈취 쉽다"→난이도는 같고 **회수 가능성**이 다르다 ③ Spring `DispatcherType`의 주어가 "인터셉터"로 미끄러짐→**Filter** ④ Order 인과 뒤집힘→**유실 방지가 목적, 사이클 끊기는 덤**(코치의 log_42 "중립 제3자" 과잉 프레이밍을 학습자가 잡음).

## 4. 결정들 (정리물의 형태)

- **표 → 파일**: CATEGORIES 한 줄은 밀도가 높고 조어가 섞여 회고엔 부적합 → 파일로 풀어씀. 용어도 학습자 지정으로 평이화(저울→**트레이드오프**, 두 갈래→**선택지**), 폴더명 `categories`→`Level2_정리`(CATEGORIES와 혼동 방지).
- **전사의 원칙**: 파일은 코치 요약이 아니라 **이미 봉인된(학습자 인출) 내용의 전사** — 1부(종합_1부)·오늘 인출이 원천. 파일 간 상호 링크로 흐름 연결(모델링→DB, 테스트→모델링·DB, 아키텍처→DB·장애).
- **로그 구조**: 종합 2부의 *내용* 로그는 Level2_정리와 중복 → 안 씀. 테스트(선행 세션)와 나머지도 **한 로그로 합침**(같은 날 같은 arc, 학습자 발의).

## 5. 아쉬운 점 (방식)

- **forward↔once 매듭에서 코치가 성급히 유보했다.** `DispatcherType.FORWARD` + OncePerRequestFilter 상호작용에서, 확실히 닫을 수 있는 걸 "미탐구로 남기자"고 물러섬 → 학습자가 **"정리하는데 자꾸 미탐구 남기는 거 싫다"**로 되잡아, **인증 vs 인가**로 갈라 그 자리에서 닫음. "틀린·막힌 건 즉시 해결"을 학습자가 코치보다 더 지킨 장면(종합_1부에 이어 반복).

## 6. 바꿀 것

- **"미탐구로 남기자"를 꺼내기 전에 자문한다: 이거 지금 확실히 닫을 수 있나?** 진짜 미확정(프로젝트 실제 설계 등)과, 원리 수준에서 닫히는 매듭을 구분한다. 원리로 닫히는 건 정리 세션에서 미루지 않는다(유보는 회피가 될 수 있다).
- 유지: 인출→대조→학습자 문장 재봉인 루프, 통짜+흐름 정리, 전제 명시, 합의 게이트 — 이번에도 안정적으로 돎.

## 7. 씨앗 (본문에만)

- **URL 입력 → 서버 도착까지의 네트워크 여정**: DNS로 IP 조회 → 라우터 → WAS 도착 → Tomcat이 하는 일. 애플리케이션 파이프라인(Spring 웹 흐름)보다 한 층 아래(네트워크). WS/WAS·서블릿 컨테이너 vs Servlet 객체 구분도 여기서. 학습자가 오늘 진짜 궁금해한 것 → BACKLOG 다음 타자.

## 한 문장 봉인

> 종합-인출은 로그를 넘어 **`Level2_정리/`라는 회고 정리물**로 결실을 맺었다 — 지도(CATEGORIES) 한 줄은 학습자용 색인, 정리물 파일은 처음 보는 사람도 읽을 수 있는 전사, 스냅샷은 방법론의 기준점. 그리고 정리 세션의 규율 하나가 굳었다: **원리로 닫히는 매듭은 "미탐구"로 미루지 않는다.**
