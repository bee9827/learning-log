# 65. 공유와 격리를 함께 얻기 — COW·PTE·페이지 크기

**날짜**: 2026-09-07

**앞선 연결**: [#64 가상주소 번역 — 페이지·프레임·MMU·TLB](64_가상주소-페이지-프레임-MMU-TLB.md)

분류: 일반 CS (운영체제/가상 메모리) — 프로젝트 외, 미러 제외

## 프로세스가 달라도 물리 페이지는 공유할 수 있다

프로세스가 다르다고 모든 물리 메모리를 두 벌로 복제할 필요는 없다. 같은 프로그램의 읽기 전용 기계어처럼 변경되지 않는 내용은 두 프로세스의 페이지 테이블이 같은 물리 프레임을 가리키게 할 수 있다.

```text
A의 코드 페이지 5 ─┐
                    ├→ 물리 프레임 20 (읽기·실행, 쓰기 금지)
B의 코드 페이지 5 ─┘
```

스택이나 힙처럼 각 프로세스에서 달라져야 하는 영역은 서로 다른 프레임에 연결한다. 격리는 모든 물리 메모리를 복제하는 것이 아니라 **페이지별 매핑과 권한을 다르게 구성하는 것**이다.

## Copy-on-Write

수정 가능한 데이터도 처음부터 모두 복사하면 대부분 읽기만 하는 상황에서 낭비다. 그래서 처음에는 물리 프레임을 공유하고 쓰기 금지로 표시한 뒤, 실제 쓰기가 발생한 페이지 하나만 복사한다. 이것이 Copy-on-Write(COW)다.

```text
A와 B가 같은 물리 프레임을 COW 상태로 공유
→ A가 쓰기 시도
→ MMU가 쓰기 금지 권한을 보고 예외 발생
→ 운영체제가 새 물리 프레임 확보
→ 기존 페이지 전체를 새 프레임으로 복사
→ A의 해당 PTE만 새 프레임을 가리키도록 변경하고 쓰기 허용
→ A의 낡은 TLB 항목 무효화
→ 중단됐던 쓰기 명령 재실행
```

**PTE는 Page Table Entry**다. 가상 페이지 하나의 물리 프레임 번호와 접근 권한 등을 담는 페이지 테이블의 항목이다. COW가 발생할 때 페이지 테이블 전체를 새로 만드는 것이 아니라 쓰기가 발생한 가상 페이지의 PTE를 바꾼다.

MMU가 COW 정책 자체를 이해하는 것은 아니다. MMU는 PTE와 TLB에 캐싱된 권한을 보고 쓰기를 막아 예외를 발생시킨다. 운영체제가 그 예외를 받아 진짜 읽기 전용 페이지인지 COW 페이지인지 판단한다.

```text
하드웨어가 제공하는 것 → 읽기(R)·쓰기(W)·실행(X) 권한과 예외
운영체제가 구현하는 것 → 그 권한과 예외를 이용한 COW 정책
```

## 페이지 크기의 저울

4KB 페이지에서 1바이트만 수정해도 운영체제는 그 바이트의 의미를 모르므로 COW 시 물리 프레임 4KB 전체를 복사한다. 페이지를 작게 만들면 COW 복사 낭비와 내부 단편화는 줄일 수 있지만, 같은 주소 범위를 표현하는 페이지와 PTE 개수는 늘어난다.

```text
16KB 주소 범위
4KB 페이지 → 페이지 4개, PTE 4개
1KB 페이지 → 페이지 16개, PTE 16개
```

페이지의 용량과 프로그램의 실제 사용률은 다르다. 4KB의 4096바이트는 모두 주소로 사용할 수 있고 PTE는 별도 페이지 테이블에 있다. **물리 프레임이 할당된 페이지 안에서** 프로그램이 일부 공간만 사용하면 내부 단편화가 생긴다.

```text
큰 페이지 → PTE 수와 관리 비용 감소 / 내부 단편화·COW 복사 낭비 증가
작은 페이지 → 내부 단편화·COW 복사 낭비 감소 / PTE 수와 관리 비용 증가
```

## 한 문장 봉인

> 공유 가능한 물리 페이지는 여러 프로세스가 함께 사용하되, COW 페이지에 실제 쓰기가 발생하면 운영체제가 그 페이지 하나만 복사하고 쓰기 프로세스의 PTE를 변경한 뒤 낡은 TLB 번역을 무효화한다.

## 학습법 회고

- COW 설명 직후 “오 재밌네”라는 명시적인 재미 신호가 나왔다. `공유 → 쓰기 감지 → 한 페이지만 복사 → 매핑 변경`이라는 원인·결과의 흐름이 자발적 설명으로 이어졌다.
- 학습자가 이미 물리주소 30KB를 계산하고 프레임 번호의 단위를 물었는데, 코치가 설명 직후 같은 내용을 다시 말하게 했다. 반복 검사로 느껴진 장면을 직접 지적한 뒤 **명확화 뒤 자동 재인출 금지**를 합의했다.
- 규칙 적용 뒤에는 MMU 같은 명확화 질문에 먼저 답하고 즉시 재서술을 요구하지 않았다. 한 회차의 관찰이므로 다음 학습에서도 재미와 흐름 유지 여부를 확인한다.
- `1KB 페이지` 질문에서 실제 사용량과 동일한 매핑 주소 범위가 섞였다. 이는 새 규칙이 아니라 기존 **유도 질문의 전제 명시**를 지키지 못한 사례다.
