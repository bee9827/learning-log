# 64. 가상주소 번역 — 페이지·프레임·MMU·TLB

**날짜**: 2026-09-07

**앞선 연결**: [#63 컴퓨터의 구성 — SSD·RAM·CPU에서 프로세스까지](63_컴퓨터의구성-SSD-RAM-CPU-프로세스.md)

분류: 일반 CS (운영체제/가상 메모리) — 프로젝트 외, 미러 제외

## 연속된 물리 메모리를 요구하지 않는 방법

프로세스 B의 모든 주소에 일정한 값 `x`를 더하는 베이스 방식은 프로세스 전체가 연속된 물리 메모리에 있을 때는 동작한다.

```text
B의 물리주소 = B 전용 베이스 + 논리주소
```

하지만 빈 RAM이 여러 곳에 흩어져 있으면 충분한 총공간이 있어도 하나의 연속 공간을 찾지 못한다. 프로세스를 LinkedList처럼 흩어진 공간에 놓고 연속처럼 보이게 하자는 생각에서, 일정한 크기의 조각과 대응 관계를 관리하는 구조로 발전했다.

- **페이지(page)**: 가상 주소 공간을 나눈 고정 크기 조각
- **프레임(frame)**: 물리 메모리를 같은 크기로 나눈 조각
- **페이지 테이블(page table)**: 각 가상 페이지가 어느 물리 프레임에 연결되는지 기록

가상주소는 `가상 페이지 번호 + 페이지 내부 오프셋`으로 나뉜다. 페이지를 다른 프레임에 연결해도 페이지 내부 위치는 변하지 않으므로 오프셋은 그대로 유지된다.

```text
페이지 크기 4KB, 가상주소 10KB
→ 가상 페이지 2 + 오프셋 2KB

가상 페이지 2 → 물리 프레임 7
→ 물리주소 = 7 × 4KB + 2KB = 30KB
```

`프레임 7`은 주소가 아니라 0부터 세는 프레임 번호다. 따라서 프레임 7의 시작 주소는 `7 × 4KB = 28KB`다.

## MMU가 주소를 번역한다

MMU(Memory Management Unit)는 현대 CPU 내부에서 가상주소를 물리주소로 변환하고 접근 권한을 검사하는 하드웨어다.

```text
CPU가 가상주소로 접근 요청
→ MMU가 페이지 번호와 오프셋 분리
→ 페이지 번호를 물리 프레임 번호로 변환
→ 프레임 번호 + 오프셋으로 물리주소 완성
→ load/store라면 CPU 데이터 캐시 확인
→ 데이터 캐시에도 없으면 RAM 접근
```

운영체제가 페이지 테이블과 권한을 만들고, MMU가 모든 메모리 접근에서 그 규칙을 빠르게 집행한다.

## TLB는 주소 번역 전용 캐시다

페이지 테이블도 메모리에 있으므로 매번 페이지 테이블과 실제 데이터를 차례로 조회하면 비용이 커진다. TLB(Translation Lookaside Buffer)는 MMU 가까이에서 최근 주소 번역 결과와 권한을 캐싱한다.

```text
TLB가 저장하는 것  → 가상 페이지 번호 → 물리 프레임 번호, 접근 권한
CPU 캐시가 저장하는 것 → 실제 명령어나 데이터(I-cache·D-cache, 또는 통합 캐시)
```

- **TLB 적중**: 이미 저장된 번역을 사용한다.
- **TLB 실패**: 페이지 테이블을 조회한 뒤 번역 결과를 TLB에 저장한다.

## 가상주소는 주소 공간 안에서만 의미가 있다

같은 프로그램을 두 번 실행해도 프로세스가 다르면 독립된 가상 주소 공간을 가진다. 같은 가상 페이지 번호가 서로 다른 물리 프레임을 가리킬 수 있다.

```text
프로세스 A: 가상 페이지 2 → 물리 프레임 7
프로세스 B: 가상 페이지 2 → 물리 프레임 12
```

따라서 주소 변환의 입력은 사실상 `현재 프로세스의 주소 공간 + 가상주소`다. TLB도 프로세스 전환 시 이전 기록을 비우거나 ASID/PCID 같은 주소 공간 식별자로 번역을 구분한다.

페이지 오프셋은 프로세스를 구분하는 값이 아니다. 페이징에서 물리주소는 **각 페이지가 연결된 물리 프레임의 시작점 + 페이지 내부 오프셋**으로 완성된다.

## 한 문장 봉인

> 프로세스마다 독립된 가상 주소 공간이 있고, 페이지 테이블이 가상 페이지를 물리 프레임에 연결한다. MMU가 페이지 번호를 번역하고 오프셋을 붙여 물리주소를 만들며, TLB는 그 번역과 권한을 캐싱한다.

## 처음 설명에서 바뀐 점

- 프로세스 전체에 `+x`를 하는 베이스 방식과 페이지 내부 오프셋을 분리했다.
- `프레임 7`은 주소가 아니라 번호이며 4KB 프레임에서는 28KB부터 시작한다고 교정했다.
- TLB에는 실제 데이터가 아니라 주소 번역과 권한이 저장된다고 구분했다.
- 같은 프로그램도 프로세스가 다르면 같은 가상주소가 다른 물리주소로 번역될 수 있음을 확인했다.
