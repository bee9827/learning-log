# 60. 카테고리 종합-인출 1부 — "외부 API 장애 대응" 신설(실패의 생애주기) + 나는 흐름으로 구조화하는 학습자

**날짜**: 2026-07-08 (메타/복습 세션 — 프로젝트 미러 제외)
**범위**: 카테고리 지도 재봉인 1부. 학습자 발의("이제 카테고리 나눌 때가 됐어"). 방식: 지도를 안 보고 카테고리별 인출(목적·저울·줄기) → 코치가 로그와 대조해 빠진 조각만 짚음 → **학습자 문장으로** 지도 재작성. DB·트랜잭션, 외부 결제 연동(+분할) 완료 — 나머지 6칸은 2부.

분류: 학습법 + 종합

## 1. DB·트랜잭션 재봉인 — 인출에서 걸러진 것들
- 통짜 인출: ACID 골격(D는 가정, A→아웃박스, I×C→동시성), 낙관 두 형태, "FOR UPDATE는 읽은 행 전부라 JOIN 조심", gap 데드락 — 최근 arc가 그대로 인출됨.
- 걸러진 구멍과 정정: ① 대들보 문장("가드는 동시성에 못 닫는다")은 인출 성공 ② **집합 vs 카운트 제약의 방향 뒤집힘** — "5명 제한을 앱으로 하기 어려워서 락"이 아니라 "**DB로 못 내려서** 락". 여기서 학습자가 더 정확하게 재정정: 중복 금지도 앱 검사(의도 표현)를 없애는 게 아니라 **경합의 진실 책임만 DB로 내리는 것** — 두 겹의 역할 분담, 서로 대체 불가 ③ 데드락 처방(재시도→409)은 인출 성공.
- **UNIQUE vs CAS는 선택지가 아니다**(학습자 발견): 탄생(INSERT, 행이 없어 CAS 걸 곳이 없음)=UNIQUE / 전이(UPDATE)=CAS — 쓰기의 모양이 배정하는 **같은 편의 두 병사**.
- 최종 저울(학습자 문장): 격리수준 vs 성능 / 낙관 vs 비관(+순서 정합성 조각 추가) / 원리: "값을 가져와서 비교하는 로직에는 틈이 있다 — 일관성은 UNIQUE(탄생)·CAS(전이)가 보장, 앱 로직은 의도 표현·친절한 거절." synchronized 가격표는 JVM 세계라 **각주로 강등**(학습자 판정: "완전히 다른 종류").

## 2. 결제 카테고리 분할 — 두 개의 칼
- 학습자: "결제는 너무 방대해서 나눠야 할 것 같아."
- **칼 1(학습자)**: 필수 vs 선택 → 코치 반격(멱등키 없는 결제 + 재시도 = 이중 결제 — 돈의 정확성 문제) → 재명명 합의: **코어(정상 세계의 필수) / 오류 케이스(실패가 존재하는 세계의 층)**. "선택"은 함정 단어 — 실패 없는 세상에서만 선택.
- **칼 2**: 오류 케이스 층을 학습자가 **사고 흐름 순으로** 3묶음: 모름과 수렴(timeout→멱등키→reconciliation) / 실패의 결말(바운드·DEAD·보상) / 방어벽(RL·CB). 코치가 비추자 — **실패의 생애주기**(진행 중→확정→번지기 전)가 나옴. ACL은 아키텍처로 이관(구현 첫 단추가 port 분리였다는 근거).
- 분할 확정: **외부 결제 연동**(코어: 인증vs승인·금액 검증·상태 기계 — "클라이언트도 외부도 믿지 않는다, 돈의 정확성은 서버가 쥔다") / 🆕 **외부 API 장애 대응**("네트워크 장애·서버 다운 같은 환경의 장애가 **우리의 장애로 전파되지 않도록** 설계한다" — 결제라는 무대에서 경험한 일반 원리들).

## 3. 학습자 자가 발견 — "나는 흐름이 중요한 사람인가봐"
- 증거 수렴: 통짜 시나리오 인출 선호(끊으면 재학습감), 흐름 정리 선행 요청, "죽은 토스의 하루" 회수 성공, 오늘의 생애주기 재배열, "사고 흐름이 이어지니까 묶자"는 클러스터링 — **정적 목록이 아니라 시간 축 서사로 구조화하는 학습자**.
- → 스킬·메모리 반영(학습자 요청): 정리·인출·분류는 "무슨 일이 벌어지는 순서로 이야기해봐요" 형태로.

## 4. 용어 평이화 스윕 (지도는 독자용 텍스트)
- 학습자가 코치 조어를 연쇄 격추: "뿌리 질문"→**목적** / "원자 장치"→풀어쓰기(UNIQUE 제약 또는 CAS — 단 "DB 제약조건(CAS)"로 묶는 건 오류라 거부: CAS는 제약이 아니라 UPDATE 문장) / "transient는 가설"→"일시적 실패는 재시도하되 한도를 둔다. 한도를 넘었다는 건 일시적이 아니었다는 뜻" / RL·CB 축약어→Rate Limit·Circuit Breaker / "개별의 계좌에 달지 않는다"→"외부 환경 문제로 인한 에러는 개별 건의 실패 횟수로 세지 않는다" / "회복탄력성"(번역어)·"실패"(한 번의 에러 느낌) 대신 **장애**.
- 원칙 재확인: 지도 문장의 기준 = "처음 보는 사람도 즉시 이해" — 코치의 압축 조어는 인출을 막는다(본인도 "정확성↔동시성"을 못 알아봄).

## 한 문장 봉인
> 카테고리 지도는 코치가 요약해주는 것이 아니라 **학습자가 인출한 문장으로 다시 꿰는 것**이다 — 인출에서 안 나오는 것(집합/카운트의 방향, DLQ라는 이름)이 곧 복습 목록이고, 인출에서 새로 태어나는 것(실패의 생애주기, UNIQUE와 CAS는 같은 편)이 곧 종합의 수확이다. 그리고 그 지도에서 결제가 두 칸으로 갈라졌다: **돈의 정확성은 서버가 쥔다**(결제 코어)와 **환경의 장애가 우리의 장애로 전파되지 않게 한다**(외부 API 장애 대응 — 실패의 생애주기: 모름과 수렴 → 실패의 결말 → 방어벽).

## 학습법 회고
- **잘된 것**: 인출→대조→학습자 문장 재작성 루프가 안정적으로 돎. 오독·방향 뒤집힘을 학습자가 "잠깐 제대로 잡고 가자"며 직접 붙듦(틀린 것 즉시 해결의 체화). 합의 게이트 아래서 코치는 조립만.
- **관찰**: DLQ — 개념(격리+알림+사람)은 완벽 생존, **이름만 휘발**(이틀 만에 "이건 뭐야?"). 용어-개념 고리는 서사보다 약하다 — 흐름 기반 학습자의 그림자면. 재방문 때 이름 인출부터.
- **바꿀 것**: 추가 없음 — 이번 세션 자체가 최근 규칙 3개(합의 게이트·통짜+흐름 정리·전제 명시)의 적용 무대였고 유지.
