# 63. 컴퓨터의 구성 — SSD·RAM·CPU에서 프로세스까지

**날짜**: 2026-09-07

**출발 자료**: gyoogle/tech-interview-for-developer의 [`컴퓨터의 구성`](https://github.com/gyoogle/tech-interview-for-developer/blob/master/Computer%20Science/Computer%20Architecture/%EC%BB%B4%ED%93%A8%ED%84%B0%EC%9D%98%20%EA%B5%AC%EC%84%B1.md)

분류: 일반 CS (컴퓨터 구조) — 프로젝트 외, 미러 제외

## 출발점

처음 알고 있던 것은 RAM이 SSD보다 빠르고 비싸며 휘발성이라는 점이었다. 저장장치의 특징을 나열하는 대신 프로그램 하나가 실행되는 시간 순서로 연결했다.

```text
SSD에 저장된 실행 파일
→ 기계 명령어와 필요한 데이터가 RAM에 올라감
→ CPU가 기계 명령어를 읽고 연산
→ 영속적으로 남겨야 하는 결과는 SSD에 저장
```

- **SSD**: 전원이 꺼져도 실행 파일과 데이터를 보존한다. RAM보다 느리지만 용량당 가격이 낮다.
- **RAM**: 실행 중인 명령어·데이터·중간 결과를 CPU가 빠르게 접근하도록 둔다. 휘발성이며 SSD보다 비싸다.
- **CPU**: RAM에 올라온 기계 명령어를 실행하고 데이터를 연산한다.

## 프로그램과 프로세스

컴파일 결과물에는 CPU가 실행할 기계 명령어가 들어 있다. SSD에 저장된 파일 자체는 **프로그램**이고, 운영체제가 실행에 필요한 메모리와 자원을 마련해 실행 중인 상태가 **프로세스**다.

```text
운영체제 → 프로세스와 메모리 자원을 만들고 관리
CPU      → 운영체제와 사용자 프로그램의 기계 명령어를 실행
```

운영체제도 CPU와 별개의 실행자가 아니다. 운영체제 코드 역시 CPU가 실행하지만, 프로세스 생성·메모리 배치·장치 관리라는 책임을 가진 소프트웨어다.

## 왜 프로세스의 메모리를 구분해야 하나

여러 프로세스가 같은 RAM 주소를 구분 없이 사용하면 한 프로세스가 다른 프로세스의 값을 덮어쓸 수 있다. 덮어쓴 값이 정상처럼 보이면 오류가 즉시 드러나지 않고 전혀 다른 위치에서 뒤늦게 터질 수도 있다.

따라서 운영체제는 각 프로세스가 자기 메모리를 사용하는 것처럼 보이게 격리해야 한다. 이 필요가 다음 노드인 **가상 주소 공간과 페이징**으로 이어졌다.

## 한 문장 봉인

> SSD의 프로그램을 실행하면 운영체제가 프로세스와 메모리 자원을 마련하고 필요한 기계 명령어와 데이터를 RAM에 올리며, CPU가 그 명령어를 실행한다. 여러 프로세스가 안전하게 함께 실행되려면 각자의 메모리 주소 공간을 격리해야 한다.

## 처음 설명에서 바뀐 점

- “컴퓨터가 프로그램을 RAM에 올린다”에서 주체를 운영체제로 구체화했다.
- CPU는 저장을 관리하는 주체가 아니라, 운영체제와 프로그램의 기계 명령어를 실행하는 하드웨어라고 분리했다.
- 프로그램 파일과 실행 중인 프로세스를 같은 것으로 보던 설명을 나눴다.
