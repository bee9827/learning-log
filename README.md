# 학습 로그 (Learning Log)

> **스스로 문제를 정의하고, 작은 실험으로 확인하며, 끝까지 풀어가기 위한 기록입니다.**

## 왜 학습 로그를 쓰나

### 만난 문제

4학년 팀 프로젝트와 취업 준비를 위해 주입식으로 공부하면서 프로그래밍의 재미를 잃었습니다. 이대로라면 이 일을 평생 할 수 없겠다는 생각이 들었고, 재미를 되찾기 위해 우아한테크코스 프리코스에 지원했습니다.

우테코 안에서도 문제는 다시 찾아왔습니다. Level 1에서는 AI가 학습을 방해할 것 같아 아예 쓰지 않았고, Level 2에서는 생각을 바꿔 AI를 써 봤습니다. 그러자 어느새 대부분을 AI에게 맡기고, 주도권을 빼앗긴 채 끌려가고 있었습니다. 이해하지 못한 코드를 작성만 하게 되면서 다시 흥미를 잃어 갔습니다.

### 풀려고 한 방식

AI를 배제하는 것도, AI에 맡기는 것도 답이 아니었습니다. 본래 목적으로 돌아가 "AI를 쓰면서도 주도권과 재미를 지키며 더 효율적으로 배우려면 어떻게 해야 할까?"를 고민했습니다. 시작은 우테코 학습법 미션에서 배운 **PiFSR**과 **나선형 학습**이었습니다.

#### 원래 개념 (출처)

두 학습법은 우아한테크코스 8기 프론트엔드 코치 시지프의 수업 자료에서 소개받았고, 백엔드 레벨2에서도 같은 자료로 다뤘습니다.

**PiFSR: 효과적인 학습 5원칙**

| 원칙 | 자료의 정의 |
|---|---|
| **P**roblem-Driven | 목적과 문제에서 시작하라. "이걸 왜 배우는가?"를 먼저 정의하고, 실제 문제를 해결하는 방향으로 학습한다. |
| **i+1** | 문제를 쪼개고, 딱 한 단계 어려운 것만 도전하라. 너무 쉽지도 너무 어렵지도 않게(comfort zone 살짝 밖), 한 단계씩. |
| **F**eedback Loop | 바로 해보고, 실패하고, 피드백을 반복하라. Do → Fail → Feedback → Iterate, Output First. |
| **S**tructural Thinking | 연결하고 구조로 이해하라. 조각이 아니라 흐름, 관계, 역할로 본다. |
| **R**esourceful | 가장 빠른 방법을 위해 모든 자원을 활용하라. 유튜브, 책, 사람, AI를 가리지 않고 비순차적으로 학습한다. |

**나선형 학습 (Spiral Learning)**: 같은 주제를 시간 간격을 두고 반복하되, 매번 더 깊고 넓게 다루는 교육과정 설계 방식입니다. Jerome Bruner가 『The Process of Education』(1960)에서 제안했습니다([EBSCO Research Starters](https://ebsco.com/research-starters/education/spiral-curriculum)). 핵심은 같은 수준에서 되풀이하는 **Repetition**이 아니라, 같은 주제를 매번 더 깊은 수준에서 다시 만나는 **Iteration**이라는 점입니다. 원래는 가르치는 쪽의 교육과정 설계 원리이고, 혼자 학습하는 데 쓰는 것은 제 적용입니다.

**i+1의 뿌리**: 언어학자 Stephen Krashen의 입력 가설(Input Hypothesis)에서 나온 표현으로, 현재 수준(i)보다 한 단계 높은 이해 가능한 입력에서 습득이 일어난다는 제2언어 습득 이론입니다([Wikipedia](https://en.wikipedia.org/wiki/Input_hypothesis)).

#### 내가 이해하고 적용하는 방식

아래는 위 개념을 제 상황에 맞게 해석한 것입니다. 원래 정의와 다를 수 있습니다.

- **Problem-Driven**: 막힌 지점을 문제로 먼저 정의합니다.
- **i+1**: 지금 할 수 있는 것보다 딱 한 단계 앞선 난이도를 고릅니다. 너무 어렵지도 쉽지도 않게, 큰 문제는 작게 나눠서 그 난이도에 맞춥니다.
- **Feedback Loop**: 이 과정에는 반드시 피드백이 함께해야 합니다.
- **Structural Thinking**: 내 생각을 구조화합니다. 정답을 받아 적지 않고 후보를 스스로 지우며 내 말로 정리합니다.
- **Resourceful**: 그 과정에서 쓸 수 있는 자원을 아끼지 않고 시도합니다.

PiFSR은 제가 원래 쓰던 방식과 매우 비슷했고, 하나를 깊게 파고드는 데 유리했습니다. 하지만 Spring처럼 범위가 넓고 제한 시간이 있는 미션에는 맞지 않았습니다. 그래서 **나선형 학습**을 함께 도입해 넓게 여러 번 돌며 바닥을 끌어올리고, 재미를 느끼는 부분에서는 PiFSR로 깊이를 더했습니다. 이 저장소의 로그 전부가 두 학습법을 적용해 온 과정입니다.

예(Iteration): 락 — #03 INSERT 경쟁 → #13 S/X락·데드락 → #17 갭락 → #26 INSERT 락 순서 → #29 갭락 재방문 → #56 실제 경합 증명

> PiFSR은 깊이를 더하는 학습법이고, 나선형 학습은 최소치를 올리는 학습법입니다. 상황에 맞게 둘을 조정해 가는 것이 이 학습 로그의 목표입니다.

**재미가 돌아온 순간**은 학습 로그를 도입하고, AI에게 정답을 달라고 하는 대신 **내 사고를 확장하는 도구**로 쓰기 시작한 때부터였습니다. 아래 규칙은 그 방식을 지키기 위해 만든 것입니다.

#### AI를 코치로 쓰는 규칙

AI를 정답 제공자가 아니라 **코치**로 쓰기로 하고, 코치가 지켜야 할 규칙을 직접 만들었습니다([나선형 학습 스킬 스냅샷](Level2_정리/나선형학습-스킬스냅샷.md)). 모든 규칙의 기준은 하나입니다.

> **최상위 목표는 재미다.** 재미는 스스로 목적과 이유를 찾아가며 파편 지식을 구조화하는 것이다. 규칙이 없는 상황에서도 "이게 나의 자가 구조화와 재미를 돕나, 훔치나?"로 판단한다.

이 기준에서 나온 규칙들입니다.

- **추측 먼저, 설명은 나중.** 모르는 개념도 바로 설명을 듣지 않고 "이름만 보고 어떤 역할일 것 같은지"부터 추측합니다. 틀려도 추측이 개념 사이 연결고리를 만듭니다.
- **정답을 먼저 받지 않는다.** 내가 던진 부분 답을 AI가 표나 원리로 완성해 주지 않고 "그래서? 왜?"로 되넘깁니다. 구조화하는 행위 자체가 학습이기 때문입니다.
- **의문 → 후보 탐색 → 후보 탈락 → 코드 적용.** 해법 후보를 넓게 펼친 뒤 "왜 안 되는지"를 스스로 찾아 지우고, 남은 이해를 실제 코드로 검증합니다.
- **구현 전 합의 게이트.** "새로 구현하는 개념에 대해서 나에게 먼저 질문해야 해. 토론하면서 의견이 일치하는 지점이 왔을 때 구현을 시작해야 해." 코드가 이해보다 먼저 가지 않도록, 이번 구현에 처음 등장하는 개념을 목록으로 깔고 토론이 수렴한 뒤에만 타이핑합니다.
- **재방문은 인출부터, 틀린 건 그 자리에서.** 전에 다룬 주제면 "전에 어디서, 왜 그렇게 했지?"를 먼저 꺼내고, 막힌 뒤에만 힌트를 받습니다. 틀리거나 막힌 부분은 다음으로 미루지 않습니다.
- **다음 키워드는 딱 한 단계 위(i+1).** 키워드 이해 → 흐름 파악 → 코드 적용 → 실전 판단 순서로 한 칸씩 올립니다. 한 번에 완벽히 이해하기보다 사이클을 유지하고, 같은 키워드를 다른 프로젝트와 깊이에서 다시 만나며 이해를 쌓습니다.

이 저장소는 그 재방문을 위한 한 곳입니다. 다시 만났을 때 "전에 어디까지 했는지"를 보고 깊이만 더합니다.

## 운영 방식

- **PR**: 큰 카테고리·학습 arc마다 브랜치와 PR 하나를 만들고, 그 순회를 마칠 때까지 같은 PR을 갱신한 뒤 `master`에 병합한다. 로그마다 새 PR을 만들지 않는다.
- **로그·커밋**: `logs/NN_핵심키워드.md` — 나중에 독립적으로 재방문할 수 있는 개념 묶음 하나. 하루나 원문 하나와 번호를 1:1로 맞추지 않으며, 한 번의 탐구에서 여러 로그가 나올 수 있다.

- **로그 작성 전**: 오늘 키워드를 이 repo에서 먼저 검색한다. 재방문이면 깊이를 더하고(중복 금지), 이전이 얕았으면 명시한다(피드백 루프).

| 로그 | 요약 |
|---|---|
| [종합_1부](logs/종합_1부_실패의생애주기-외부API장애대응신설-흐름기반학습자.md) | 카테고리 종합-인출 1부 — DB 재봉인(집합/카운트 재정정·UNIQUE와 CAS는 같은 편) + 결제 분할 → **외부 API 장애 대응 신설(실패의 생애주기 3장)** + 흐름 기반 학습자 자가 발견 |
| [종합_2부](logs/종합_2부_6칸재봉인-Level2정리폴더신설.md) | 종합-인출 2부 — 6칸(테스트·인증·모델링·아키텍처·Spring웹·학습법) 재봉인 + **`Level2_정리/` 폴더 신설**(카테고리 9칸 파일 + 스킬 스냅샷). 정리물은 요약이 아니라 **인출의 전사**. Spring웹 *미탐구* 탈출 |
